## Schema and supporting additions

The original additive migration creates 12 isolated tables. Existing employees, users, companies, departments, designations, locations and fiscal years are reused. `employees.employee_no` is the code and `display_name` is the name. Since 2 November 2026, leave eligibility uses the shared HRIS Employee status master (`employment_statuses`, such as Permanent, Probation and Contract). Employees and leave policies reference that master through `employment_status_id`; renaming a master status does not break the connection. The separate `employees.employment_status` value (Active/Inactive/On leave/Exited) remains the record lifecycle state and is labelled Record status in the employee form.

Migration `2026_11_02_001000_link_hrla_employee_statuses.php` adds nullable foreign keys and a policy uniqueness key of status ID + leave type. It links existing employee and policy classifications only when their normalized names match one unambiguous HRIS status. Unmatched legacy classifications remain intact and unlinked; HR must assign their HRIS status before a leave policy can apply. Historical approval snapshots are preserved. The legacy employment-type columns remain for compatibility, but do not drive policy matching. Employee forms and policy setup use the same status master; legacy employee API payloads are linked when an unambiguous status-name match exists. Approval rechecks the employee’s current HRIS status.

* `shifts`: stable ID, name, original time boundaries and explicit next-day flag. Duplicate names are allowed.
* `shift_assignments`: employee, shift, inclusive effective range, actor. Overlap is rejected. New versions store the resolved shift ID/name/start/end, preserving history across setup edits.
* `holidays`, `leave_types`: configurable source fields; optional explicit paid/unpaid/unspecified metadata has no payroll effects.
* `leave_policies`: HRIS employee-status ID/leave-type key, distinct allowance state and nullable numeric annual allowance. Numeric policies apply automatically to that status and approved leave is deducted by calendar year. Zero is preserved; blank/as-needed are not converted to zero/unlimited. Referenced approved policies cannot be edited/deleted.
* `leave_applications`: requester and subject, type, form date, range, chargeable days, reason, state, approval policy snapshot. A Leave Type selector is a necessary addition missing from the workbook form.
* `leave_decisions`: unique application, outcome, decision actor/reason/time.
* `correction_requests` and `correction_decisions`: pending proposed punches, expected base version, structured reason/client, unique decision and actor/time.
* `attendance_versions`: append-only through application endpoints; original punches, shift snapshot, committed actor/time/source/reason, correction approval link, import batch and physical row. There is deliberately no employee/date unique constraint. Latest committed timestamp then ID wins deterministically. Pending/rejected requests never enter the version table.
* `import_batches`: unique file SHA-256, server actor/time, scalar extracted rows, headers, confirmed mapping, preview/results and commit marker. Raw uploads remain PHP temporary uploads and are not published or retained. Parsed provenance is retained privately in the database.
* `settings`: reserved module settings; no data is inserted. Empty configuration uses the user-confirmed secondary-reporting approval rule. The implemented workflow keeps HR leave pending and half-day activation disabled.

Foreign keys restrict deletion of referenced audit data. Indexes support effective assignment, daily version selection and leave coverage. Approval and version transitions lock the subject employee and request in transactions, with unique decision/correction/import-row constraints. Remaining allowance is derived from approved chargeable leave in each calendar year; there is no separate mutable balance counter to deduct twice. Approval locks and rechecks the policy and each affected year's usage.

## Authorization and workflows

Active existing admins/HR managers retain organization-wide scope, matching this project's existing HR permissions (there is no current per-user company tenancy mapping). Other users can see their own employee and direct reports. Primary reporting grants management authority. Secondary reporting grants it **only when `dual_reporting` is enabled**, as confirmed by the user; either manager may decide. No synthetic supervisor role or transitive reporting authority is introduced. Every module route rechecks active-user access; selectors, previews, exports, imports, histories and decisions are scoped server-side.

Employee correction identity is always taken from the session, ignoring a tampered employee ID. HR/supervisor direct entry checks reporting scope, commits immediately, and records the current user. A user cannot directly enter or approve their own attendance; they use a pending correction. Self-approval means either approving one's own employee record or one's own submitted request, even for HR. If only one HR user exists and no authorized alternate supervisor/HR user is available, their own submissions remain pending until another existing authorized person can decide; no accounts are created automatically.

Current punches/base version are loaded from the effective version. New punches are full business-local timestamps and may be blank. Attendance remarks are optional for Missed punch, Client meeting and Correction; Other requires nonblank remarks. The form's required indicator updates with the reason type, and server validation enforces the same rule. Optional blank remarks are stored as an empty string without changing the audit schema. Client-meeting reasons still require a client name. Stale correction or direct forms fail and require reload. Approval/rejection decisions still require their own reason. Approval appends a version atomically, preserving the previous one. Requests are visible in authorized HR/supervisor inboxes; routing is an inbox workflow, with no email/external messaging added.

Leave applications always start Pending, including HR submissions (confirmed safeguard). Only approved leave affects attendance. The server calculates and previews the inclusive working-day count using one shared calendar service, rejects all-day-off ranges, checks joining date and working-day overlaps with pending/approved applications, and revalidates on approval. Missing or incomplete policies allow a pending request but block approval; configured numeric policies enforce the annual allowance on submission and approval. Numeric allowances apply to the selected Employee status and automatically deduct approved leave for January–December. A cross-year request is split by its working dates and must fit each affected year's allowance; approval is atomic across all years. Each January starts a fresh allowance without carrying unused days forward.

## Attendance/report rules

Time entry uses a segmented 12-hour control: separate hour (1–12) and minute (00–59) number fields plus an AM/PM selector. There is no seconds entry and no free-text time box. Shift setup and attendance punches share this control, with server-side validation and unchanged-second preservation.

Clock inputs and outputs use `h:mm AM/PM` (for example `9:05 AM` or `10:00 PM`) across shift setup, attendance entry, history, approvals, upload preview and CSV exports. Punches keep separate calendar dates, including next-day checkout. Original seconds remain stored and are retained when an unchanged minute is resubmitted; duration and status calculations still use the originals. Changing a visible minute enters that minute at `:00` seconds. Elapsed durations remain hours/minutes/seconds without AM/PM. Existing strict `YYYY-MM-DD HH:MM:SS` upload/API values remain supported for compatibility and second-level precision, while user-facing displays omit seconds.

Status precedence: Day off → approved Leave → Missing Time Out → Missing Time In → Missing shift configuration → in-progress/future or completed Absent → punctuality. Both blank punches become Absent only after the scheduled shift ends; no attendance row is required. The register builds the employee/date calendar and bulk-joins effective versions, assignments and approved leave. Missing schedules remain actionable; no schedule is invented. Dates before joining are excluded.

Rounding is temporary, nearest half hour with exact ties rounded up, carrying into the next date when needed. Shift boundaries and 30-minute grace thresholds remain exact. Rounded arrival strictly later than start+30 is Late; rounded departure strictly earlier than end−30 is Early off. Combined `Late / Early off` retains both flags. Recorded punches, Work Hours, Actual Hours and Diff are never rounded. Durations use seconds, shown `hours:minutes:seconds`, including negative Diff. Incomplete punches produce null Work Hours and Diff; no synthetic punch is created. Original punches still appear on days off and leave days.

Daily register: inclusive range up to 31 dates and 10,000 employee dates; company/department/employee/status filters; 50-row pagination; scoped CSV export. Correction and leave inboxes have date/company/department/employee/outcome filters, pagination and authorized CSV exports (up to 10,000 requests). History shows all committed versions and provenance. The register uses bulk queries rather than issuing a query for every employee/date. CSV neutralizes leading formula characters; HTML is escaped by Blade. Work/Actual/Diff are durations, not paid/overtime hours.

Attendance-register Company, Department, Employee and Day Status filters support multiple checkbox selections, option search, Select shown, Clear and Done. No selection means all authorized records. Choices within a filter are combined with OR; filters are combined with AND. Status categories also match combined outcomes (Late includes Late / Early off). Selections persist in pagination and use the same query for CSV export. Legacy single-value URLs remain supported. Every selected employee is checked against the user's authorized scope; a mixed authorized/unauthorized selection is rejected in full.

## Supported spreadsheet upload

Open **HRLA Dashboard → Attendance upload**. Supported files: XLSX, XLS, XLSM, XLTX, XLTM, XLT, ODS, OTS, CSV and TSV. The downloadable XLSX template is optional. Only the first worksheet is read. Header aliases are proposed (`Code`/`employee_code`/`employee_no`, `Date`/`shift_date`, `Time In`/`time_in`, `Time Out`/`time_out`), but an HR user must confirm four distinct mapped columns and preview validation results.

Reader selection follows file contents rather than the filename extension. Device exports containing HTML tables, SpreadsheetML XML or delimited text named `.xls` are supported, as are recognizable workbooks with a mismatched supported extension. HTML extraction reads scalar table text only; scripts, styles, images and embedded objects are removed without executing or fetching them. XML entities are rejected. Unreadable, encrypted and malformed files still return a validation message.

| Field | Required format |
|---|---|
| `employee_no` | Exact existing employee code, formatted as Excel Text to retain leading zeros |
| `shift_date` | Text `YYYY-MM-DD` |
| `time_in` | Text `YYYY-MM-DD h:mm AM/PM`, for example `2026-10-30 10:00 PM`, or blank |
| `time_out` | Text `YYYY-MM-DD h:mm AM/PM`, or blank; use the next date explicitly for overnight shifts |

Workbook cells with date/time formatting are normalized automatically, including the 1904 calendar. Text and zero-padded employee codes retain leading zeros. CSV supports comma, semicolon, tab or pipe separators; TSV uses tabs. UTF-8 (with or without BOM) and BOM-marked UTF-16 are supported. Quoted text and blank punches are preserved. Formula cells are rejected without evaluation, and macros are not executed. Limits: 5 MB uploaded, 25 MB expanded/500 entries for ZIP workbooks, 40 columns, 2,000 data rows plus up to 30 heading rows (workbook first-sheet extent: 2,031 rows) and 2,000 characters per cell.

### Variable report layouts

The importer scores the first 30 nonempty rows to find likely headers below report titles and strips exact repeated headers. HR can choose a different header from these source rows; doing so resets mapping and reviewed edits. The original extracted source, detected header and ignored repeated-header row numbers are retained in the existing batch mapping JSON. No schema change is needed. Broader column aliases cover badge/staff/employee identifiers, names, arrival/departure, first/last punches and timestamp/direction logs. Unique known-code and date value profiles can suggest columns with unfamiliar labels; ambiguous candidates require manual mapping.

HR chooses daily paired rows or separate IN/OUT logs, numeric date order and employee matching. Exact employee codes take precedence; automatic matching also accepts a unique normalized name or uniquely matching unpadded numeric code. Exact-code-only mode disables this fallback. Duplicate names and ambiguous identifiers remain invalid. Database employee IDs and unknown device state numbers are never guessed.

Dates recognize year-first, day/month/year, month/day/year and common named-month formats; 12/24-hour clocks retain seconds. Auto date order uses valid unambiguous dates across the file and can resolve an ambiguous date when a full check-in timestamp identifies the same date. Unresolved dates remain flagged until HR chooses an order or edits them. Excel serial dates and fractional-day times are normalized using the workbook calendar, defaulting to the standard 1900 calendar for text exports or older batches without calendar metadata. Clock-only punches use the assigned shift boundary, choosing the nearest same/next date for overnight shifts. Full timestamps retain their date. Derived attendance dates use nearby assigned overnight boundaries. Unassigned/uncertain cases need explicit correction. Original source values remain separate from normalized and manually edited values.

Formatting is repaired before validation on initial mapping and every review, including manual edits and pasted values. Repairs cover extra/Unicode spaces, dotted AM/PM, one-digit minutes, missing seconds, compact HHMM times, named-month dates and missing-punch markers. The selected-row inspector lists automatically fixed fields. Existing previews have **Fix formats & validate**, which rechecks every row without resetting edits or rereading the upload. Its date-order selector can resolve the whole file in one action. Stale-tab revision checks still apply. Readable clock values with an unresolved date remain visible in AM/PM format; validation reports the date problem without redundant clock-format errors. A clock without a resolved full date can never become a saveable record. Invalid dates, ambiguous identities, unassigned shifts and stale attendance remain errors rather than being silently guessed.

Separate logs require an employee, full timestamp and recognized IN/OUT direction (IN/OUT, I/O, check-in/check-out, clock-in/clock-out, entry/exit, sign-in/sign-out). Unsorted logs group by employee/attendance date, retaining the earliest IN and latest OUT with a visible grouping note. All contributing source row numbers remain in batch results and attendance provenance. Late overnight checkout can belong to the prior shift date. Unknown directions and malformed rows stay visible and invalid instead of being discarded. Blank/missing punches retain existing missing-punch statuses. Monthly matrix reports, merged employee blocks and vendor-specific numeric state meanings are not automatically interpreted; they need explicit mapping or an additional reviewed layout rule.

After mapping, HR reviews an editable table with employee codes, attendance dates, assigned shifts, separate check-in/check-out dates, 12-hour hour/minute controls, calculated durations and validation messages. Filters show all, valid, invalid or excluded rows; pages contain 50 rows. Include/exclude controls apply to the current page or individual rows. Validate edits before paging, filtering or saving. Draft validation saves reviewed values in the import batch without writing attendance. Rebuilding the mapping restores the original Excel values and resets reviewed edits.

The Verify & save page is an attendance database preview with four editable spreadsheet columns: A employee code (resolves the database employee_id), B shift_date, C time_in and D time_out. Shift, status and worked hours are calculated and read-only. Cells support click/Shift-click range selection, keyboard navigation, rectangular tab-separated paste and range copy/cut. The toolbar can copy, move or swap mapped columns, or fill a destination from an original uploaded column. Column operations affect only included rows on the current page. ## Confirmed decisions, proposed supporting designs and inactive gaps

1. **Supporting design:** explicit inclusive shift assignments with newest-saved priority on overlapping dates; explicit same/next-day shifts. Committed version snapshots retain original boundaries.
2. **User-confirmed connection (2 November 2026):** Employee status comes from the shared HRIS status master. Both employee profiles and leave policies use its stable ID; record Active/Inactive lifecycle values do not control eligibility.
3. **User-confirmed annual rule (2 November 2026):** allowances reset every calendar year, January–December. Custom allowance dates and policy eligibility/deduction switches are removed. Approved leave is deducted automatically; requests crossing years are checked against each year's allowance. Accrual, prorating, carry-forward and opening balances remain inactive. Existing fiscal-year data remains available to the rest of HRIS.
4. **Confirmed safeguard:** as-needed and unspecified policies are represented distinctly and cannot approve leave until a defined business rule is implemented. No unlimited entitlement is assumed.
5. **Optional explicit metadata:** paid/unpaid is never inferred from a code and does not affect payroll.
6. **Confirmed safeguard:** half-day submissions are disabled pending session, multi-day counting and attendance treatment. Internal calendar arithmetic preserves eligible 0.5 units and zero excluded dates, but this does not activate half-day leave.
7. **User-confirmed:** HR leave stays pending; either primary or enabled secondary supervisor may approve, with self-approval prevented. No auto-approval bypass is exposed.
8. **Confirmed precedence:** approved full-day leave wins over punches on working days; punches and durations remain visible. Punctuality uses combined flags when no leave/day-off overrides status. Leave-with-punch reconciliation has no salary consequence.
9. **Supporting safeguard:** attendance punctuality is recalculated from saved original punches and shift snapshot. Current day-off/approved-leave status is evaluated at report time. Holiday changes intersecting approved leave and edits to used policies are blocked pending a reviewed reconciliation rule; pending applications are recalculated at approval. Stale corrections/import previews are rejected.
10. **Inactive:** approved cancellation, balance restoration and post-approval leave amendment. Do not edit approved rows directly.
11. **Supported adapter:** first-sheet spreadsheet and delimited-text upload as above. Machine API, protocol, credentials and device adapters remain unconnected.

## Recurring holidays

Holiday Setup uses a name and one date field in `DD/MM` format in both add and edit forms; no year is entered or displayed. Clicking the field or calendar icon opens a month/day calendar with month navigation and selectable valid days, including February 29. Keyboard users can open it with Arrow Down, navigate days with arrows/Home/End, select with Enter and close it with Escape. Typing four digits also inserts the separator automatically. The holiday list displays the same day/month format. Each holiday repeats annually in attendance status and leave-day calculations. Invalid month/day combinations are rejected, February 29 applies only in leap years, and duplicate month/day entries are blocked, including duplicates of older year-specific records.

The existing DATE column stores new/edited entries against the leap-year anchor `2000`; the anchor is an internal compatibility detail. Calendar calculations compare month/day for both anchored and older records, so existing holiday entries are interpreted as annual holidays without rewriting stored rows. No schema migration is required. Adding, editing or deleting a holiday checks every affected annual occurrence against approved leave, including occurrences in other years, and blocks changes that need reconciliation.
